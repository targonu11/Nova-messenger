## Что делать, если не работает (локально)

Типичные ошибки в браузере и что с ними делать.

### Ошибка 500 на `/api/users/me`, `/api/users`, `/api/groups`

**Причина:** на порту 3001 крутится **старый** процесс сервера (до исправления JWT). Новый код не подхватился, пока старый не остановлен.

**Решение — перезапустить сервер:**

1. Закрой все окна терминала, где был запущен Nova (`start-all.bat`, `npm start` и т.п.).
2. Если не помогло — убей процесс на порту 3001 в PowerShell **от администратора**:

```powershell
netstat -ano | findstr ":3001"
taskkill /PID НОМЕР_ИЗ_СТОЛБЦА_PID /F
```

3. Запусти заново:

```powershell
cd "C:\Users\roman\Downloads\ьфч\server"
npm.cmd start
```

4. В другом терминале — клиент:

```powershell
cd "C:\Users\roman\Downloads\ьфч\client"
npm.cmd run dev
```

5. Обнови страницу в браузере (F5). Если всё ещё 500 — **выйди из аккаунта и войди снова**.

**Проверка, что сервер живой:** открой http://localhost:3001/api/health — должно быть `{"ok":true,...}`.

---

### Красная полоска «Подключение к серверу отклонено»

**Причина:** WebSocket не принял токен (устаревший сервер или просроченная сессия).

**Решение:**

1. Перезапусти сервер (см. выше).
2. Выйди из Nova и войди снова.
3. Убедись, что сервер запущен **до** открытия браузера.

---

### PowerShell: `npm` заблокирован

Используй **`npm.cmd`** вместо `npm`, или запускай `.bat` файлы двойным щелчком.

Один раз можно разрешить скрипты:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

---

### Ошибка Vite «Failed to parse source» в `appSettings.js`

**Причина:** синтаксическая ошибка в файле (обычно незакрытая `{`).

**Решение:** обнови проект до последней версии файлов или проверь, что в `client/src/appSettings.js` объект `defaults` заканчивается на `};`.

---

### Голосовые: «В текст» не расшифровывает

Нужен ключ Whisper в `server/.env`:

```env
GROQ_API_KEY=gsk_...   # бесплатно: console.groq.com
```

После добавления — **перезапуск сервера**.

## Часть 1. Создание виртуальной машины в Яндекс.Облаке

1. Откройте https://console.cloud.yandex.ru/ и войдите в аккаунт Яндекс.
2. Создайте каталог: **Каталоги** → **Создать каталог** → имя `nova-messenger` → **Создать**.
3. Перейдите: **Compute Cloud** → **Виртуальные машины** → **Создать виртуальную машину**.
4. Заполните:
   - **Имя:** `nova-server`
   - **Зона:** `ru-central1-a`
   - **Образ:** Ubuntu 22.04 LTS
   - **Платформа:** Intel Ice Lake, **2 vCPU**, **4 ГБ RAM**
   - **Диск:** SSD, **20 ГБ**
   - **Публичный IP:** включить
5. В разделе **Сетевые настройки** нажмите **Создать новую** группу безопасности:
   - Имя: `nova-security-group`
   - Добавьте входящие правила:

     | Протокол | Порт | Источник   |
     |----------|------|------------|
     | TCP      | 22   | 0.0.0.0/0  |
     | TCP      | 80   | 0.0.0.0/0  |
     | TCP      | 443  | 0.0.0.0/0  |

   - Сохраните группу.
6. В разделе **Доступ**:
   - Логин: `ubuntu`
   - Добавьте SSH-ключ: **Создать новый ключ** или вставьте свой публичный ключ из `C:\Users\ВашеИмя\.ssh\id_rsa.pub` (если ключа нет — создайте: `ssh-keygen -t rsa -b 4096` в PowerShell).
7. Нажмите **Создать**, дождитесь создания VM.
8. Запишите **публичный IP** виртуальной машины (например `158.160.12.34`). Он понадобится везде дальше вместо «ваш-ip».

## Часть 2. Установка на сервере (вручную)

### 2.1. Подключение по SSH

В PowerShell (или терминале):

```powershell
ssh ubuntu@ваш-ip
```

Подставьте свой IP вместо `ваш-ip`. При первом подключении подтвердите вопрос про fingerprint — напишите `yes`.

### 2.2. Установка Node.js, Nginx и PM2

На сервере (после `ssh ubuntu@ваш-ip`) выполните по очереди:

```bash
sudo apt update && sudo apt upgrade -y
```

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

```bash
sudo apt install -y nginx
sudo npm install -g pm2
```

```bash
mkdir -p ~/nova-messenger/server ~/nova-messenger/client
```

### 2.3. Загрузка файлов сервера на VM

**Вариант A — с вашего компьютера (PowerShell), из папки проекта:**

```powershell
cd "C:\Users\roman\Downloads\ьфч"
scp -r server\* ubuntu@ваш-ip:~/nova-messenger/server/
```

Не копируйте папку `server\node_modules` — на сервере зависимости поставятся отдельно. Если `node_modules` попала в архив — на сервере можно удалить: `rm -rf ~/nova-messenger/server/node_modules`.

**Вариант B — через WinSCP/FileZilla:**  
Подключитесь по SFTP к `ваш-ip`, пользователь `ubuntu`, ключ или пароль. Скопируйте всё содержимое папки `server` (кроме `node_modules`) в `/home/ubuntu/nova-messenger/server/`.

### 2.4. Запуск бэкенда на сервере

Снова по SSH:

```bash
cd ~/nova-messenger/server
npm install
```

Создайте файл окружения:

```bash
cp .env.example .env
nano .env
```

В открывшемся редакторе задайте (подставьте свой IP):

```
PORT=3001
NODE_ENV=production
DOMAIN=ваш-ip
```

Сохраните: `Ctrl+O`, Enter, выход: `Ctrl+X`.

Запуск и автозапуск:

```bash
pm2 start index.js --name nova-server
pm2 save
pm2 startup
```

Команда `pm2 startup` выведет свою команду (типа `sudo env PATH=... pm2 startup ...`). Скопируйте и выполните её целиком.

### 2.5. Настройка Nginx

Создайте конфиг (подставьте свой IP в `server_name`):

```bash
sudo nano /etc/nginx/sites-available/nova
```

Вставьте (замените `ваш-ip` на реальный IP):

```nginx
server {
    listen 80;
    server_name ваш-ip;

    location / {
        root /home/ubuntu/nova-messenger/client/dist;
        try_files $uri $uri/ /index.html;
        index index.html;
    }

    location /api {
        proxy_pass http://localhost:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    location /socket.io {
        proxy_pass http://localhost:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /uploads {
        proxy_pass http://localhost:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

Сохраните (`Ctrl+O`, Enter) и выйдите (`Ctrl+X`). Затем:

```bash
sudo ln -sf /etc/nginx/sites-available/nova /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

Проверка: в браузере откройте `http://ваш-ip/api/test` — должен вернуться JSON `{"status":"ok"}` или подобный ответ от API.

## Если что-то не работает

- **Не открывается сайт:** проверьте группу безопасности в консоли Яндекс.Облака — порты 80 и 443 должны быть открыты для 0.0.0.0/0.
- **Ошибка при SSH:** проверьте, что используете правильный ключ и логин `ubuntu`.
- **API не отвечает:** на VM выполните `pm2 status` и `pm2 logs nova-server`; проверьте, что в `.env` указан верный `DOMAIN=ваш-ip` и перезапустите: `pm2 restart nova-server`.
- **После обновления кода:** снова загрузите файлы сервера, на VM выполните `cd ~/nova-messenger/server && npm install && pm2 restart nova-server`. Клиент пересоберите с тем же `VITE_API_URL` и заново загрузите `dist` в `~/nova-messenger/client/`.
